# 设计原则（裁决红线）

> 本文件是后续改动的裁决依据：当「方便」「跟上游一致」与本文冲突时，以本文为准。
> 从 MisaTV 相关讨论里我们只承认**原则**，不承认任何具体代码实现。

## 1. MIT / GPL 红线：只搬规则，不搬代码

本仓是 **MIT**；MisaTV（yagami-hue/MisaTV，Flutter/Dart、GPL-3.0）是同作者的另一个完整项目。
借鉴 MisaTV 只允许借鉴**行为与规则**，流程固定为：

1. 先把候选写成**中文验收规格**：输入 / 输出 / 边界 / 失败态，写清楚再动手；
2. 工程实现必须**独立编写**，不照抄其源码结构、命名与分支顺序；
3. PR 描述标注「**规则借鉴、独立实现**」，便于日后审计。

**禁止**将 MisaTV 的 `.dart` 源码、注释、README 段落、错误文案或默认配置字面量
原样带入本仓，也禁止逐行翻译后带入。若某段确需直接复用，必须取得 yagami-hue 的
**书面双许可**（MIT 侧与 GPL 侧同时授权）并经架构评审记录，否则一律视为 **GPL 污染**，不得合入。

## 2. 不做假开关

底层没有接口就不做 UI 开关。开关必须**真实改变行为**，并有测试证明它确实改变了行为。

反例（本仓明确不做）：

- 没内置 ffmpeg / MPV 时，配置页不许摆一个假的「启用硬件解码」开关 —— 如实提示「依赖缺失」即可；
- macOS 上没开 `com.apple.security.app-sandbox`，就不给 app 加沙盒 entitlement 或「文件访问授权」开关 ——
  加了惰性无效，正是本节反对的假开关（详见 `docs/macos-build.md`「为什么不开 App Sandbox」）。

判据：能指出这行代码在执行前后有什么**可观测差异**，并且有测试断言过这个差异。

## 3. 不内置源、内容责任归用户

本仓只做**工具外壳**，不内置任何影视 / 直播源，也不替用户挑选内容。
用户自行导入的第三方内容，其合法性由**用户自己负责**。

任何面向用户的过滤 / 屏蔽功能，文案必须表述为「**你自己在你的设备上隐藏**」，
不得表述为内容审查、合规能力或平台侧的过滤承诺 —— 本仓不提供、也不声称提供任何审查能力。
